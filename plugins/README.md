# Breezell Plugin Market

This folder is the Breezell plugin market. Breezell reads `index.json` from here (GitHub first, then
the jsDelivr mirrors) and lists the plugins under **Breezell Console › Plugins**, where they can be
searched, filtered by category, browsed page by page, installed and updated.

**Building a plugin?** This page is the overview. The whole guide is in [`docs/`](docs/README.md): getting
started, `package.json`, permissions, every call of the API, errors, limits, each topic, publishing and
recipes. Every new plugin also gets an AI skill made from the same pages
(see [Working with an AI assistant](#working-with-an-ai-assistant)).

| Path | Contents |
|---|---|
| `index.json` | The market index (generated by the devkit, do not edit by hand) |
| `blocklist.json` | Plugins Breezell turns off and will not install (edited by the maintainers) |
| `packages/<publisher.name>/plugin.json` | A plugin's details and all its versions |
| `packages/<publisher.name>/<version>/*.vsix` | The packages (a published version never changes) |
| `devkit/breezell-plugin.mjs` | The devkit: create, build, pack (open or closed source), submit, check |
| `devkit/breezell.d.ts` | The plugin API typings |
| `devkit/templates/`, `devkit/templates.json` | Templates for new plugins (Breezell's "Create a plugin" uses the same) |
| `devkit/skill/` | The AI skill every new plugin gets (`.agents/skills/breezell-plugin/`), with `docs/` as its references |
| `docs/` | The plugin guide |
| `examples/` | Source of the example plugins, one per kind of plugin (below) |

## What a Breezell plugin is

A Breezell plugin is a VS Code extension with a `breezell` object in its `package.json`:

```json
"breezell": {
	"apiVersion": 1,
	"permissions": ["chat.events"],
	"source": "open"
}
```

- It can use the whole VS Code extension API: commands, webview panels, the status bar, settings and so on.
- Give it `"extensionKind": ["ui", "workspace"]` (the templates do). In a remote (WSL, SSH) window it then
  runs on the user's computer, next to Breezell, so `vscode.breezell` is there even when the remote server
  is an older build.
- It also gets `vscode.breezell` to work with Breezell, limited to the permissions it declares.
- Plugins run only while the user is **signed in to Breezell**. Signing out turns them off, and
  `vscode.breezell` refuses every call.
- A plugin works the same whether or not it is in the market: install your own `.vsix` from
  **Plugins › Installed › Install local .vsix**.

## Kinds of plugins

| Kind | What it is | Example | Template |
|---|---|---|---|
| **Pack** | No code: skills, rules for the AI, MCP servers and themes declared in `package.json` | [Starter Pack](examples/starter-pack) | Pack |
| **Panel** | A panel inside Breezell with your own page (a webview), following the conversation | [Focus Player](examples/focus-player) | Panel |
| **AI** | Commands that use the user's chat model | [Doc Writer](examples/doc-writer) | AI command |
| **Window** | A window of its own with your page and layout; it can also open without the editor | [Focus Timer](examples/focus-timer) | Window |
| **Conversation** | Reads the user's conversations, sends messages and approves tool calls, shown in its own window or panel | [Chat Mirror](examples/chat-mirror) | Window |
| **Screens** | Buttons, pages, restyled parts, drawn code fences and modes in Breezell's own screens | [Desk Pet](examples/pet) | — |
| **Companion** | A pet on the chat box that follows what the AI is doing | [Desk Pet](examples/pet) | — |
| **Long-running** | Keeps a conversation going until something is done, with limits and a page of its own | [Goal](examples/goal) | — |

The kinds combine: one plugin can bring skills, a panel, AI commands and a window. For a large plugin
with its own settings page, data downloaded from a GitHub release and a part installed in the system, see
[Breezell IME](examples/ime).

## Getting started

**In Breezell**

Open **Breezell Console › Plugins › Develop**, fill in the id and name, choose a template (Pack,
Panel, AI command, Window or Minimal) and how to publish it (open or closed source), then pick a
folder. Open the new folder in a new window.

**From the command line** (Node.js 18 or later)

```bash
curl -O https://raw.githubusercontent.com/BreezellCode/BreezellCode/main/plugins/devkit/breezell-plugin.mjs
node breezell-plugin.mjs init my-plugin --id my-name.my-plugin --display-name "My Plugin" --template webview
cd my-plugin
npm install
```

Then open the folder in Breezell and press **F5**: the plugin runs in a development window.

| Command | What it does |
|---|---|
| `npm run build` / `npm run watch` | Bundle `src/extension.ts` into `dist/extension.js` with esbuild |
| `npm run typecheck` | TypeScript type check |
| `npm run validate` | Check `package.json` |
| `npm run package:open` | Pack as **open source**: the source and source maps ship in the package |
| `npm run package:closed` | Pack as **closed source**: minified code only (including the js and css in `media/`), no source, no source maps |
| `npm run submit -- --market <clone of the market>` | Add the package to the market (see [Publishing](docs/publishing.md)) |

Step by step, with what a new plugin holds and how to try it: [Getting started](docs/getting-started.md).

## The plugin API: `vscode.breezell`

The typings are in [`devkit/breezell.d.ts`](devkit/breezell.d.ts); the templates already have them in
`types/breezell.d.ts`. In other editors `vscode.breezell` is `undefined`, so check it before use.

| API | Permission | What it does |
|---|---|---|
| `breezell.apiVersion`, `breezell.permissions` | — | The API version and the permissions this plugin declared |
| `breezell.account.isSignedIn`, `onDidChangeSignIn` | — | Whether the user is signed in to Breezell |
| `breezell.language`, `onDidChangeLanguage` | — | Breezell's display language (`en`, `zh-CN`, `zh-TW`, `ja`, `ko`, `ru`, `es`, `pt-BR`), for a plugin's own texts: `vscode.env.language` does not follow it. Check for it: an older Breezell does not have it |
| `breezell.chat.onDidStartTurn`, `onDidFinishTurn` | `chat.events` | A conversation turn started or finished: mode, outcome (completed, error, stopped) and duration, **never the content** |
| `breezell.chat.listConversations()`, `getConversation(id)`, `onDidChangeConversation`, `show(id)` | `chat.read` | The conversations of this workspace as the user sees them: messages, replies (with reasoning), tool calls with their parameters, status and result, and the memories used for each message (`recalledMemories`, and `memoryUse` with the chat's resident and relevant counts); the reply being written; open one in Breezell's chat |
| `breezell.chat.send(text, { conversationId, automated, mode, model, attachments })` | `chat.send` | Send a message as the user would, or start a conversation; the AI answers it like the user's own. `automated`: the plugin sends it on its own (see [Work over many turns](docs/chat.md#work-over-many-turns)). `mode` (`normal`, `agent`, `plan`) and `model` (one of `models.list`) as the pickers set them; `attachments`: up to 10 files or folders of the workspace |
| `breezell.chat.stop(id)` | `chat.send` | Stop the reply a conversation is writing, as Stop does. It is not the user's Stop: `automated` messages may follow |
| `breezell.chat.holdDoneNotice(id)`, `releaseDoneNotice(id, { announce })` | `chat.send` | No done sound or system notification until the work is over (see [Work over many turns](docs/chat.md#work-over-many-turns)) |
| `breezell.chat.conversationOfTurn(turnId)` | `chat.read` | The conversation a turn event was about, as `listConversations` names it |
| `breezell.chat.approve(id)`, `reject(id)` | `chat.approve` | Approve or reject the tool call a conversation waits for |
| `breezell.models.request({ messages, system, model, responseFormat, maxOutputTokens, onText, onReasoning }, token)` | `models.request` | Send a request to the user's current chat model, or to `model` (one of `models.list`), optionally streaming. User messages may carry `images` (base64, up to 8). `responseFormat: 'json'` gives the answer parsed in `json`; `maxOutputTokens` caps the answer |
| `breezell.models.list()`, `select({ provider, model })` | `models.select` | The models of Breezell's model picker, and switching the chat model to one of them |
| `breezell.providers.listCustom()` | `providers.read` | The user's custom APIs as their settings page shows them: base URL, protocol, request address, **API key**, request headers, account pool, models and prices |
| `breezell.providers.list()` | `providers.list` | The same custom APIs **without** keys, header values or paths: name, protocol, host, header names, models |
| `breezell.app.requestRestart({ scope, reason, l10n, force })` | `app.restart`; `app.forceRestart` to force | Ask to restart the plugins, this window or all of Breezell, or restart them without asking (see [Restarting Breezell](docs/restart.md)) |
| `breezell.windows.open(id)` | — (the window is declared in `package.json`) | Open one of the plugin's windows; returns it with `postMessage`, `onDidReceiveMessage`, `onDidClose`, `close` |
| `breezell.tools.register(name, { invoke })` | `agent.tools` | Give Breezell's agent a tool the plugin declares and runs, in the chat modes it picks (see [Agent tools](docs/agent.md#agent-tools)) |
| `breezell.tools.registerCallHandler(handler)`, `onDidRunTool` | `agent.hooks` | See each tool call of the agent before it runs, and refuse it; hear how each went (see [The agent's tool calls](docs/agent.md#the-agents-tool-calls)) |
| `breezell.permissionState(permission)`, `requestPermission(permission)`, `onDidChangePermissions` | — (only permissions it declared) | Where a permission stands, asking the user at a moment of the plugin's choosing, and hearing when they change it |
| `breezell.chat.readInput()` | `chat.input` | What is in the chat box, its part before the caret, and the recent messages of the conversation |
| `breezell.chat.registerSendHandler(handler)` | `chat.intercept` | See each message before it is sent: change it or stop it (see [A message before it is sent](docs/chat.md#a-message-before-it-is-sent)) |
| `breezell.ui.onDidOpenSurface` | — (the page is declared in `package.json`) | One of the plugin's pages opened; returns it with `context`, `postMessage`, `onDidReceiveMessage`, `onDidClose` (see [Changing Breezell's screens](docs/ui.md)) |


Every call with its options, results, errors and limits: [API reference](docs/api.md). What each permission
gives and when the user is asked: [Permissions](docs/permissions.md).

## Working with an AI assistant

Every plugin made from a template (in Breezell or with `breezell-plugin.mjs init`) has:

- `.agents/skills/breezell-plugin/`: a skill with the workflow, the rules, a checklist and the pages of
  `docs/` as its references. Breezell's own agent finds it in the plugin's folder, as do other tools that
  read `.agents/skills`.
- `AGENTS.md`, and `CLAUDE.md` pointing to it: what any assistant should read first.

None of them goes into the package. For a plugin made before they existed, copy
[`devkit/skill/SKILL.md`](devkit/skill/SKILL.md) to `.agents/skills/breezell-plugin/SKILL.md` and the pages
of `docs/` to `.agents/skills/breezell-plugin/references/`.

## Publishing

Fork this repository, pack the plugin (`npm run package:open` or `package:closed`), run
`npm run submit -- --market <your clone>`, then open a pull request. The market check runs on it and a
maintainer reviews it. How it works, what review looks at, open or closed source and the blocklist
(`blocklist.json`, edited by the maintainers): [Publishing](docs/publishing.md).
