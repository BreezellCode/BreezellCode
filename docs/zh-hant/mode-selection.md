# 模式選擇

Breezell 提供多種工作模式，以適應不同程度的自主性、深度和工作流程控制。Agent 是預設模式，也是大多數工作的建議自動工作流程。

當你想要更具體的互動方式（例如快速對話、唯讀分析、編輯前規劃、更深入的因果推理或平行 AI 隊友）時，可以使用其他模式。

## Chat

Chat 用於快速提問和回答。

當你想詢問程式碼、解釋想法、比較選項或快速取得回答，而不希望 Breezell 自主編輯檔案或執行工具時，請使用 Chat。

在 Chat 模式中，模型無法編輯檔案。

## Agent

Agent 允許 Breezell 檢查專案、編輯檔案、使用工具、執行命令並完成編碼工作。

大多數開發工作都適合使用 Agent。它是預設模式，因為它可以自動選擇合理的工作流程、收集所需內容、進行變更，並在交付前驗證結果。

## Analyze

Analyze 用於唯讀調查。

當你希望 Breezell 檢查程式碼、診斷問題、審查架構或稽核行為而不修改檔案時，請使用 Analyze。當你需要在決定修改內容前取得技術結論時，它非常有用。

## Plan

Plan 會在編輯前建立結構化的實作路徑。

對於複雜功能、大型重構、需求不明確，或需要在開始程式碼變更前做出設計決策的工作，請使用 Plan。

提示：在 Agent 模式中，如果工作需要結構化的實作路徑，Breezell 可能會決定切換到 Plan。你可以允許或拒絕切換。如果啟用了全自動模式，Breezell 會在適當時自動確認切換。

## Entanglement

Entanglement 使用因果推理和內容感知來處理更深入的產品與程式碼決策。
Entanglement 由 Breezell 獨立研究和發布。它是 Breezell 專屬的模式，在整個網路上都很獨特。

如需了解其因果狀態追蹤和驗證閉環的技術概覽，請參閱 [Entanglement 模式功能說明](/zh-hant/entanglement-mode-overview)。

當你想要更具體的互動方式
當請求依賴意圖、取捨、隱藏原因、情緒細節或多步驟推理，且需要的不只是直接回答時，請使用 Entanglement。

提示：此模式可以大幅提升模型能力，但比標準工作流程消耗更多資源。其副作用尚不明確。

提示：由於 Entanglement 內容已經注入，在同一對話中從 Entanglement 切換到 Agent 並不能完全停用 Entanglement 行為。對話仍會保留 Entanglement 功能並繼續消耗資源。如果想返回一般 Agent 工作流程，請開始新的對話。

## Teams

Teams 協調多個 AI 隊友，以處理大型功能和並行工作流程。

當工作可以拆分為相互獨立的工作流程（例如研究多個領域、比較實作方案，或同時推進大型專案的多個部分）時，請使用 Teams。

提示：此模式可以大幅提升模型能力，但比標準工作流程消耗更多資源。

限制：並行隊友之間的讀寫衝突仍可能限制 Teams。Breezell 會努力減少這些衝突，但大型並行工作可能仍然更難協調；如果多個隊友修改互相重疊的區域，也可能造成混亂。

## 選擇模式

對於大多數工作，請保留預設的 Agent 模式。只有當工作明確需要不同工作流程時才切換模式。

| 模式 | 最適合 |
| --- | --- |
| Chat | 快速對話和簡短說明 |
| Agent | 預設編碼工作流程、檔案編輯、工具和驗證 |
| Analyze | 唯讀診斷、審查和架構調查 |
| Plan | 變更前的結構化實作規劃 |
| Entanglement | 深入的因果推理和內容感知決策 |
| Teams | 大型或獨立工作流程中的平行 AI 隊友 |
