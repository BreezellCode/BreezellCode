# Entanglement 模式

> 為複雜和不確定的問題提供結構化調查支援的工作模式。

## Entanglement 可以做什麼

Entanglement 適用於原因不明確、可能需要多次檢查的工作。它協助 Breezell 在工作過程中保持清晰的調查脈絡。

- 調查未知 Bug 和回歸問題。
- 關聯多個檔案或模組中的線索。
- 整理假設、有用證據、後續步驟和結論。
- 支援使用工具進行檢查和後續驗證。
- 在結構化面板中顯示調查進度。
- 保存有用結論，方便之後重新處理類似問題。

## 可以看到什麼

從模式選擇器中選擇 Entanglement 後，Breezell 可以顯示：

- 目前調查階段。
- 正在分析的假設及其支援證據。
- 計畫中的檢查和驗證結果。
- 目前信心度和已確認的結論。
- 需要重新檢視先前方向時的糾偏資訊。

## 什麼時候使用

以下情況適合使用 Entanglement：

- 根因未知。
- 問題涉及多個檔案、模組或系統。
- 需要在修改程式碼前比較不同解釋。
- 需要透過後續測試或觀察確認結果。

對於明確、範圍有限的修改或日常編碼工作，預設的 Agent 模式通常更合適。

## 如何開始

1. 在模式選擇器中選擇 Entanglement。
2. 描述問題症狀、目標和相關限制。
3. 允許 Breezell 檢查調查所需的內容。
4. 檢視面板中顯示的假設、檢查項目和結論。
5. 如果需要更多證據或驗證，繼續對話。

## Entanglement 與 Agent

Agent 是一般開發工作的預設模式。Entanglement 面向需要更謹慎推理和後續檢查的問題。

請選擇符合工作需求的模式。直接實作可以使用 Agent，不確定或多步驟的調查可以使用 Entanglement。

## 重要說明

Entanglement 面板用於輔助決策。套用重要變更前，請檢查其中的結論和驗證結果。
