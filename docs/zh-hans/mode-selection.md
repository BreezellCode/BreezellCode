# 模式选择

Breezell 提供多种工作模式，以适应不同程度的自主性、深度和工作流控制。Agent 是默认模式，也是大多数任务推荐的自动工作流。

当你想要更具体的交互方式（例如快速对话、只读分析、编辑前规划、更深入的因果推理或并行 AI 队友）时，可以使用其他模式。

## Chat

Chat 用于快速提问和回答。

当你想询问代码、解释想法、比较选项或快速获得回答，而不希望 Breezell 自主编辑文件或运行工具时，请使用 Chat。

在 Chat 模式中，模型无法编辑文件。

## Agent

Agent 允许 Breezell 检查项目、编辑文件、使用工具、运行命令并完成编码任务。

大多数开发工作都适合使用 Agent。它是默认模式，因为它可以自动选择合理的工作流，收集所需上下文，进行更改，并在交付前验证结果。

## Analyze

Analyze 用于只读调查。

当你希望 Breezell 检查代码、诊断问题、审查架构或审计行为而不修改文件时，请使用 Analyze。当你需要在决定修改内容前获得技术结论时，它非常有用。

## Plan

Plan 会在编辑前创建结构化的实现路径。

对于复杂功能、大型重构、需求不明确，或需要在开始代码修改前做出设计决策的工作，请使用 Plan。

提示：在 Agent 模式中，如果任务需要结构化的实现路径，Breezell 可能会决定切换到 Plan。你可以允许或拒绝切换。如果启用了全自动模式，Breezell 会在合适时自动确认切换。

## Entanglement

Entanglement 使用因果推理和上下文感知来处理更深入的产品与代码决策。
Entanglement 由 Breezell 独立研究和发布。它是 Breezell 独有的模式，在整个网络中具有独特性。

有关其因果状态追踪和验证闭环的技术概览，请参阅 [Entanglement 模式功能说明](/zh-hans/entanglement-mode-overview)。

当你想要更具体的交互方式
当请求依赖意图、权衡、隐藏原因、情绪细节或多步骤推理，且需要的不只是直接回答时，请使用 Entanglement。

提示：此模式可以大幅提升模型能力，但比标准工作流消耗更多资源。其副作用尚不明确。

提示：由于 Entanglement 上下文已经注入，在同一对话中从 Entanglement 切换到 Agent 并不能完全禁用 Entanglement 行为。对话仍会保留 Entanglement 能力并继续消耗资源。如果想返回普通的 Agent 工作流，请开始新对话。

## Teams

Teams 协调多个 AI 队友，以处理大型功能和并行工作流。

当任务可以拆分为相互独立的工作流（例如研究多个领域、比较实现方案，或同时推进大型项目的多个部分）时，请使用 Teams。

提示：此模式可以大幅提升模型能力，但比标准工作流消耗更多资源。

限制：并行队友之间的读写冲突仍可能限制 Teams。Breezell 会努力减少这些冲突，但大型并行任务仍可能更难协调；如果多个队友修改相互重叠的区域，也可能造成混乱。

## 选择模式

对于大多数任务，请保留默认的 Agent 模式。只有当任务明确需要不同工作流时才切换模式。

| 模式 | 最适合 |
| --- | --- |
| Chat | 快速对话和简短解释 |
| Agent | 默认编码工作流、文件编辑、工具和验证 |
| Analyze | 只读诊断、审查和架构调查 |
| Plan | 更改前的结构化实现规划 |
| Entanglement | 深入的因果推理和上下文感知决策 |
| Teams | 大型或独立工作流中的并行 AI 队友 |
