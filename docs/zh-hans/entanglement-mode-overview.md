# Entanglement 模式

> 为复杂和不确定的问题提供结构化调查支持的工作模式。

## Entanglement 可以做什么

Entanglement 适用于原因不明确、可能需要多次检查的任务。它帮助 Breezell 在工作过程中保持清晰的调查脉络。

- 调查未知 Bug 和回归问题。
- 关联多个文件或模块中的线索。
- 整理假设、有用证据、后续步骤和结论。
- 支持使用工具进行检查和后续验证。
- 在结构化面板中展示调查进度。
- 保存有用结论，方便之后重新处理类似问题。

## 可以看到什么

从模式选择器中选择 Entanglement 后，Breezell 可以显示：

- 当前调查阶段。
- 正在分析的假设及其支持证据。
- 计划中的检查和验证结果。
- 当前置信度和已确认的结论。
- 需要重新审查之前方向时的纠偏信息。

## 什么时候使用

以下情况适合使用 Entanglement：

- 根因未知。
- 问题涉及多个文件、模块或系统。
- 需要在修改代码前比较不同解释。
- 需要通过后续测试或观察确认结果。

对于明确、范围有限的修改或日常编码任务，默认的 Agent 模式通常更合适。

## 如何开始

1. 在模式选择器中选择 Entanglement。
2. 描述问题症状、目标和相关限制。
3. 允许 Breezell 检查调查所需的上下文。
4. 查看面板中显示的假设、检查项和结论。
5. 如果需要更多证据或验证，继续对话。

## Entanglement 与 Agent

Agent 是通用开发工作的默认模式。Entanglement 面向需要更谨慎推理和后续检查的问题。

请选择与任务相匹配的模式。直接实现可以使用 Agent，不确定或多步骤的调查可以使用 Entanglement。

## 重要说明

Entanglement 面板用于辅助决策。在应用重要更改前，请检查其中的结论和验证结果。
